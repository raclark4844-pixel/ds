# Native ds Lead Generator upgrade

This is the existing TanStack Start/Vite website, not a Next.js app. Better Auth's existing organization/member/session tables remain authoritative. The customer workspace is `/sales-desk` on the same origin, linked from `/workspace`; no new repository, application or subdomain is required. Employee tools retain their separate access boundaries.

## Implemented, with activation held

- Fresh server sessions, verified email, active membership and scoped role checks. A client organization owner is not a platform administrator. Missing/revoked/ambiguous membership fails closed.
- Parameterized tenant restrictions for leads, activity, enrichment, campaigns, webhook logs and settings. Composite foreign keys reject cross-company associations. Status updates use optimistic versions and record activity in the same statement. Message drafts use idempotency keys and do not send outreach.
- Native Checkout and Stripe webhook endpoints; trusted server-owned customer/price/organization mappings; exact-origin checks; signature verification; durable event receipts and current-subscription reconciliation instead of granting access from old invoice events.
- Integer microdollar accounting, database reservations, atomic Redis counters, unknown-outcome holds, frozen daily allocation and markup, verified receipt deduplication, transactional Stripe outbox, per-customer leased delivery and bounded retries.
- Exported Grok extraction, Claude proposal and ChatGPT support JSON schemas/prompts. Output validation rejects authority-bearing extra fields, invented citations and unknown catalog references. Prices render separately from approved catalog data. Signed callbacks atomically store tenant activity, documents/enrichment and escalation intents; a leased worker posts escalation intents to configured Base44 team routing. These contracts are not activated Base44 workflows.

## Base44 callback and escalation protocol

`POST /api/webhooks/base44` is disabled unless `BASE44_CALLBACK_ENABLED=true`. Set server-only `BASE44_INTEGRATION_SECRETS_JSON` to a JSON object keyed by integration ID, with each value containing `orgId` and a random `secret` of at least 32 characters. Each integration has exactly one authorized tenant. Never expose this configuration in the widget or browser.

The UTF-8 JSON body has exactly `envelope`, `leadId`, `input`, `output`. The envelope uses the exported schema; the input/output use its named node. Sign the exact raw body using HMAC-SHA256 over `timestamp + "." + body`. Headers are `x-dts-integration`, `x-dts-timestamp` (Unix seconds), `x-dts-signature` (hex). Header timestamps expire after five minutes. For retries sign the same body with a fresh header timestamp; preserve requestId and issuedAt. Body age is limited to 24 hours. A changed body using the same tenant/requestId conflicts. No caller-controlled actor is persisted: the integration identity becomes the actor. Leads must already belong to the bound organization.

Acceptance is HTTP 202 with `{accepted:true,requestId,escalation:"queued"|"none"}`. It does not mean a person was notified. Validation errors never enter the activity feed. A duplicate valid body does not duplicate the feed or escalation. A new valid Grok/Claude callback updates the corresponding tenant lead's enrichment/document in the same statement as its receipt and activity record.

Configure server-only `BASE44_TEAM_ROUTING_JSON` keyed by organization ID; each entry contains `endpoint` (an exact HTTPS `app.base44.com` function URL without credentials/query/fragment), `secret` (at least 32 random characters), and `idempotencyVerified:true`. Set that last flag only after verifying the Base44 receiver deduplicates `Idempotency-Key` before any team notification, retains the key for at least 24 hours, verifies the HMAC/timestamp and organization binding, and resolves recipients from administrator-approved team settings. The sender never accepts recipients from a model.

Run `node --import tsx scripts/base44-escalation-worker.ts` from the existing scheduler only after setting `BASE44_ESCALATION_WORKER_ENABLED=true`, the routing configuration and the test database. Schedule it frequently enough for the intended notification latency; no scheduler was activated here. Payload fields are `version`, `requestId`, `orgId`, `event:"support.escalation"`, and `data:{reason,summary}`. Headers include `Idempotency-Key`, `x-dts-timestamp` and `x-dts-signature` using the same HMAC convention. The receiver must return exactly `{accepted:true,requestId}` after durable acceptance. The local record then becomes `acknowledged`, not `delivered`. Network/server failures retry with the same identity, up to six attempts within 22 hours; terminal/missing-routing cases require reconciliation.

- Use Stripe test mode for Checkout completion, delayed payment, subscription cancellation, duplicate/reordered webhooks, meter acceptance, asynchronous meter rejection and invoice totals. No live Stripe charge has been exercised.
- Exercise the Redis Lua scripts on isolated Redis with concurrent clients and network failures. Local tests currently verify fail-closed provider admission; they do not substitute for a real Upstash service test.
- Connect provider receipts and channel importers; configure the Base44 receiver and verified recipients. Test retries, signed callbacks and escalation deduplication without real outreach.
- Confirm Vercel Git deployment controls, complete review and obtain release authorization before removing the hold or enabling production flags.
